# Result format v1

`scripts/lab.py validate FILE` is the executable validator. JSON rejects non-finite constants on input; output writing forbids NaN/Infinity. This lightweight format deliberately has no schema-library dependency.

Required top-level fields: `schema_version` (integer 1; Boolean true is rejected), `mode` (`fixture` or `measured`), `created_utc` (parseable timestamp with explicit UTC offset), exact `config`, `model_metadata` (must be null in fixture mode), `batches`, and `unmeasured`. The complete implemented list of unmeasured limitations must be retained. Measured runs must also record a nonempty `ollama_version`, metadata name matching the configured model, a nonempty digest, positive integer size, and a details object containing format/family/parameter-size/quantization (nullable when unavailable). Metadata emitted by the client is allowlisted. Results do not store endpoint, generated response text, thinking content, raw error messages or private evidence.

Each expected `(concurrency, repeat, workload)` combination must appear exactly once. Each batch contains that tuple, a strictly positive finite `wall_seconds`, finite nonnegative aggregate throughput and exactly `concurrency` requests in a list. Repeats are zero-indexed in JSON. Each request contains workload and status (`ok` or `error`). Errors have `error_type`; successful requests have wall time, nullable TTFT, metrics and quality. TTFT cannot exceed wall time. Metric counts/durations are nonnegative integers, rejecting booleans; rates must match counts/durations and cached prompt accounting. Zero-duration rates are null; rate fields themselves are required. Batch throughput must match successful output token count divided by batch duration. Quality `passed` must be a Boolean, and `grader` must match the mode: `exact-json-v1` for measured results, `fixture-synthetic-not-model-output` for fixtures. Exact JSON grading compares types recursively, so Boolean true or float 1.0 cannot substitute for integer 1. Malformed containers and missing fields produce validation errors.

Configuration accepts exactly the eight keys shown in the example files and rejects unknown settings. Concurrency is a unique subset of 1/2/4, repeats 1–3, context 256–8192, output cap 1–512, timeout 1–120 seconds and seed 0–2147483647. Workloads must be supported unique string IDs; lists/objects and other unexpected types are rejected cleanly. The validator checks execution-critical structure, required provenance and metric consistency. It cannot authenticate truthful timestamps, genuine model identity, raw server claims or substantive benchmark credibility. A determined editor can forge JSON; this is validation, not cryptographic attestation. Owner review and environment evidence remain necessary. Unknown extra result fields are not a privacy guarantee: review all artifacts before sharing.
