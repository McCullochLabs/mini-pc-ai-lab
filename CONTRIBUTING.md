# Contributing

Contribute only original or appropriately licensed material you have authority to share. Original code contributions follow MIT; original documentation/report contributions follow CC BY 4.0. See [licensing boundaries](LICENSING.md). Third-party material requires verified redistribution rights and its own notices.

Submit small, reproducible changes with a clear explanation and relevant test evidence. Python standard library implementations are preferred. Keep fixtures synthetic and licensed for redistribution. Never contribute source or assets from private commercial projects.

Run `python -m unittest discover -s tests -v`. Label all sample data as fixtures. Results must identify hardware, model artifact, software versions, settings, trial count, errors, and missing measurements. Do not collapse different workloads into one score.

Discuss new dependencies, model downloads, stress tests, and infrastructure before adding them. No contributor may publish private evidence or accept partnership terms on behalf of the owner. Report sensitive findings privately to the owner; a public reporting address has not yet been established.
